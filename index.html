Checks

What a verdict proves — and what it doesn't

  • PASS proves the listed checks passed at run time. It does not prove the task was good, complete, or honest — only that its receipts checked out.
  • FAIL means at least one check's observed evidence contradicted the claim. The evidence is in the record — argue with the evidence, not the badge.
  • PARTIAL means something could not be verified (network error, timeout, CORS block). Unverifiable is reported as unverifiable — never rounded up to a pass.
  • URL checks in the browser are subject to CORS: a site that blocks cross-origin reads will ERROR here and PASS in the CLI. The CLI is the authority for URL checks.
  • File checks are sandboxed to one base directory. Paths that escape it are rejected and reported as ERROR — never silently read.
  • This is heuristic triage for orchestration claims, in the spirit of the Trust Fabric: receipts over assertions, evidence over adjectives.

Verify it yourself

Don't take our word for it — re-run the check from your own machine or your own agent runtime.

  • In your browser: cli/verify.js — the zero-trust CLI checker: run node cli/verify.js manifest.json; exit 0 = PASS, 2 = FAIL, 3 = PARTIAL.
  • From your agent runtime: cwi-mcp-server — CWI's read-only MCP server. Call trust_verdict: the evidence-bound scoring engine behind task verdicts, callable from any MCP client. Zero-trust guide: VERIFY.md.
